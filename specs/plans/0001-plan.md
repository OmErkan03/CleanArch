## Risks & open questions
1. **Environment** — doctor on this machine: profile fast runnable, profile full runnable;
   prerequisites met (`dotnet` ≥ 10). Docker 29.5.2 (linux) answers `docker info`, so the new
   `requires test-integration` will be met here; GitHub `ubuntu-latest` runners ship Docker too.
   Recommendation: no environment action needed.
2. **`Program` visibility** — ASP.NET Core 10 generates a public `Program` for top-level statements,
   so `WebApplicationFactory<Program>` should work without touching production code. Recommendation:
   try without; if it does not compile, add the one-line `public partial class Program;` (R-7: behavior-neutral).
3. **Eagerly read options** — `Program.cs` reads `TokenOptions`, `MfaOptions`, Redis and Postgres
   settings at builder time. Recommendation: supply them with `builder.UseSetting(...)` in
   `ConfigureWebHost` (visible to eager reads), not `ConfigureAppConfiguration` (applied too late).
   Keys generated per run: JWT key (≥ 32 bytes) and MFA key (Base64 of 32 random bytes).
4. **SDK 11 and VSTest** — the machine builds with SDK 11.0.100; `dotnet test` runs in VSTest mode
   unless a `global.json` opts into Microsoft.Testing.Platform. Recommendation: use VSTest with
   `--filter` (trait syntax `Category=Integration`); if SDK 11 refuses VSTest, stop and raise it
   as R-07 (plan drift) rather than switching runners silently.
5. **Testcontainers reaper (Ryuk)** — containers are disposed by the fixture; Ryuk removes leftovers
   from a killed run and exits ~10 s after the run. Recommendation: AC-7 reads `docker ps -a`
   after that window; keep Ryuk enabled (safety for killed runs).
6. **Local `appsettings.json` change** (uncommitted connection string) — overridden by the test
   settings, never relied on. Recommendation: leave it out of every commit, as before.
7. **Integration budget** — first run pulls `postgres:17-alpine` and `redis:7-alpine` (already
   local for `docker-compose`). Recommendation: measure the medians in step 3 against the ≤ ~2 min budget.
8. **Fixture in the fast profile** — the fast step filters the whole solution; xUnit v3 may create the
   integration assembly's fixture even when the filter selects none of its tests, which would start
   containers in fast (AC-1). Recommendation: check it in step 2 (`docker ps` during `--fast`); if it
   happens, start the containers lazily on first use of the factory — the split stays selector-based.
