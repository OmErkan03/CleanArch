## Risks & open questions
1. **Environment** — doctor: profile fast runnable, profile full runnable; prerequisites met
   (`dotnet` ≥ 10, `docker info`). Recommendation: no action.
2. **Admin bootstrap** — no admin is seeded; the claim API itself needs `Admin`. Recommendation:
   one EF write through the app's own `UludagDbContext` (load user, add the `Admin` claim, save) —
   arrange only, no raw SQL (banned); every other claim goes through the real API.
3. **Claims reach the session** — BR-16 says claim changes reach active sessions immediately;
   the helper still grants claims before the user logs in, so tests do not depend on BR-16.
4. **TOTP** — codes are single-use per 30 s per user (BR-14); each test user confirms once, so no
   wait is needed. Codes come from the secret returned by `/mfa/setup` (Otp.NET).
5. **Parallelism** — xUnit runs classes in parallel on one shared app/database. Recommendation:
   every test creates its own users and products with unique names (GUID suffix) and never
   asserts global counts (AC-13).
6. **Contract questions found while planning** — `POST /api/auth/register` returns 200 + id (not
   201). It is outside Product scope: no assertion on it beyond success; noted, not a finding here.
7. **Coverage tooling** — coverlet.MTP adds `--coverlet` options to the test app; the run is made
   with the integration project alone, outside check (`dotnet test --project … --coverlet
   --coverlet-output-format cobertura`), and only the summary is shown. If the extension's
   options differ in 10.1.1, the plan's command is adjusted, not the tool (R-07 if a new tool is needed).
8. **Deviations make AC-7/8/9 partly "bug entry" instead of "test"** — expected by the spec (AC-11);
   the reviewer and QA check that each failing expectation was recorded, not dropped.
